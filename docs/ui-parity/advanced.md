# Advanced tab — content parity

Everything the current Advanced tab shows and does, taken from the running code at `e5af886f`
(`frontend/templates/advanced/tab.html` and the twenty files under `frontend/templates/advanced/tab/`,
`frontend/templates/shared/navigation.html`, `index.html`, the scripts under `advanced/auth/`, `advanced/json-editor/`,
`advanced/editor/`, `advanced/ui/`, `main.js`, `shared/ui/navigation.js`, `shared/ui/status.js`, `shared/ui/core.js`,
`shared/ui/ceremony-result.js` over `shared/ceremony/result.js`, `advanced/credential-display/list-render.js` and
`registration-result.js`, the styles under `frontend/static/styles/`) and the server routes it calls
(`server/app/routes/advanced/`). The charter (`docs/UI_MIGRATION.md`, "Content parity") requires every item to be mapped
to the new component and checked in a browser before the phase that ports it is done. The saved credentials, which the
tab shows in a column beside its form, and a credential's details and registration view are in
`docs/ui-parity/credentials.md` (CRED-L, CRED-C, CRED-M, CRED-G).

Phase 29 is split: **29A** ports the tab's frame (the Registration / Authentication switch, the toolbar, the saved
credentials as a drawer, the result panel), the JSON editor and the request both it and the form show, the registration
form and the registration ceremony with its result; **29B** the authentication form, the authentication ceremony and its
result. The Phase column says which.

Scripts are under `frontend/static/scripts/` unless another path is given; templates under `frontend/templates/`.
"Verbatim" text is quoted exactly; `${...}` marks a value filled in at run time; ¶ marks a paragraph break in the markup
(`<br><br>`). The **New** column is filled in when the item is ported: the component (under `web/src/components/` unless
another path is given), the test that holds it, and how it was checked in a browser.

The words themselves are not copied: every sentence from logic comes from the modules `web/` imports (`@legacy/*`);
`tests/app/tooling/test_web_source_rules.py` fails if `web/src` redefines one of their exports or repeats one of their
sentences. Only the templates' own text (headings, labels, options, placeholders, titles, the info popups, the errors
the templates hold) is written in the components.

## What changed (29A)

Nothing the registration side of the tab shows or does was dropped, except what is listed here with its reason.

- **Layout.** The form is four section cards (User Identity, Authenticator Selection, Other Options, Extensions), each
  a grid set by a container query (one, two or three columns as the card has room); from 1280 px the JSON editor sits
  beside them, sticky under the header and as tall as the window, below that under the form. The saved credentials are
  a drawer from the toolbar, not a column (ADV-D1). The toolbar holds the Registration / Authentication switch, Saved
  Credentials with the count, Reset and Create Credential, the result panel under it.
- **Fields.** One field row everywhere; switches for single booleans, toggle chips for the algorithms (ML-DSA-44, -65
  and -87 together under "PQC") and the hints; byte values in Geist Mono with their refresh button inside the field.
  A disabled field is white and faded, never a grey block; text fields show no focus effect.
- **The JSON editor (the owner's choice, 2026-09-28).** Save is gone: an edit applies as it parses. The form follows
  every edit it can read; an edit that does not parse says the parser's sentence and where (line and column, with Go to
  line), one a check refuses says the check's sentence, and in both cases the form keeps the last request it could read.
  The text is what Create Credential sends, as today. "JSON changes saved successfully!", "Save", its title and its
  failure sentence are not shown. The editor's × and its expand / collapse are not ported (ADV-Z3: the current page
  never shows them). The keys a request carries beside `publicKey` now survive a form change (the current editor drops
  them at the next one); the toolbar's Reset drops them. A form change no longer rebuilds over an edit when only the
  saved credentials changed.
- **Read back in both UIs.** The editor's reading of a request now holds everything the form writes: largeBlob, the prf
  switch, and a missing attachment as Unspecified (it read as Cross-Platform); an empty exclude list leaves the switch
  as it was (`readCreationOptions`; `build(read(build(s)))` equals `build(s)` for every setting).
- **Messages.** A success and the server's warnings are toasts, as today; a failure stays in place, in red, until the
  next ceremony (the Simple tab's rule, Phase 28A). The fake credential IDs' length error and truncation notice stay
  under the field rather than as toasts. Create Credential is busy, and Reset unusable, while a ceremony runs.
- **The result.** The registration opens in Phase 28B's dialog at its registration level, the credential's detail one
  Back below it, rather than in the current second modal; closing it returns the focus to Create Credential.
- **Fixed in both UIs** (28B's findings, each with a test failing before): an AAGUID stored as base64url is read as
  base64url, not as hex, in the list, the detail and both views, and the authenticator data's hash is computed from its
  base64url; a certificate's version reads "3 (0x2)", not "3 (0x2) 0x2"; a certificate known only by its summary keeps
  it in the attestation's JSON (no `{certificateIndex}` left); the current UI's second modal shows the registration its
  buttons belong to, not the last one composed.
- **Not ported:** the flat create / assert JSON mode and the settings navigation (ADV-Z1, Z2), which the page never
  reaches.

## The parity check (29A)

`web/e2e/advanced-parity.spec.ts` compares the current Advanced tab at `/` with `/beta#advanced` in Chromium, against
Flask serving the export under the strict CSP. Result on 2026-09-28:

- **The registration form's words**, section by section (`readShownText` / `compareShownText`, `web/e2e/parity.ts`; the
  popups, the checkboxes' own labels and the hidden errors set aside and compared on their own): the same four
  headings and the same words, **no difference**.
- **The info popups:** all 18 of the registration form, the same labels in the same order ("(hex)" included), and the
  same English and 中文 text.
- **The choices:** the algorithms and the hints, the same labels in the same order.
- **The request:** for the same User ID, user name and challenge, the editor's text with the defaults and with fifteen
  settings changed (attachment, resident key, attestation, exclude credentials, timeout, two algorithms, a hint,
  minPinLength, credProtect, largeBlob, prf and its first evaluation) is **equal byte for byte**.
- **The result:** a registration made in `/beta#advanced` (Chromium's virtual authenticator) shown in the current UI's
  modal and in `/beta`'s detail and registration levels: the same words, the only differences the three
